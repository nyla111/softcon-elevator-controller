# Part 3: Access & Panels

## Overview

Part 3 authorizes destination-floor requests before Dispatch receives them. The real
`AccessManager` is registered as `ctx.services["access"]` by `ems/access/__init__.py`.
Simulator `PassengerArrived` events are handled by `AccessManager.on_passenger()`.

## Main API

- `permission(credential_id) -> Permission`: checks the ACS through FR-49's fallback.
  A valid result includes allowed floors, default floor and roles. During an ACS
  timeout, recent eligible cached permissions may be returned; otherwise private
  floor access is denied.
- `public_floors(at_time) -> set[int]`: returns the lobby and any floors opened by
  the Facility Manager's daily schedule. The lobby remains available for exit.
- `on_passenger(event)`: checks the destination against public floors, card rights,
  courier restrictions and lockdown. Accepted requests publish `CallRequested`;
  rejected requests publish `AccessRefused` and a generic `PanelMessage`.
- `tap_card(...)` / `choose_other_floor(...)`: use the default floor and optionally
  replace it within five simulated seconds, preserving the original wait clock.

## Panels and security

`RefusedPanel` publishes a generic public-facing explanation and a list of
currently available public floors. Detailed refusal reasons and credential IDs
belong in `AccessRefused` and security-only logs, not in the public panel text.
`AccessLogging` records accepted/replaced/refused card activity, with a 90-day
retention policy and Security-only access.

## Demo: one refused destination

Run `uvicorn ems.web.server:app --reload`, then open
`http://localhost:8000/panel/`.

- **Refused:** card `card-L5-001`, destination **L18**.
- **Allowed:** same card, destination **L5**.

The panel sends the input to `POST /api/access/panel/request`, which publishes
`PassengerArrived` to the real Access service. The response displays the actual
`PanelMessage` for refused requests. The example card is generated by Part 1's
mock population; it is an L5 employee card, not a hard-coded fake permission.
The demo endpoint is for the local simulator and is not a production authentication API.

for passenger movement. The panel page is a basic demonstration interface, not
an operational deployment.
